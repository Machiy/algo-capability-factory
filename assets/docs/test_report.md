# 算法能力验证报告模板（能力抽取源 · 模拟业务材料）

> 本文件为本项目构造的**报告模板与历史样例**，不是本项目的实测结果。
> 实际验证报告由 P2/P3 的 validator 生成到 `outputs/reports/`。

## 1. 四层验证检查项

| 层 | 检查项 | 判定方法 |
|---|---|---|
| 接口规范 | `build_pipeline()` 签名 | AST 解析函数签名 |
| 接口规范 | 输出列 `pd` / `label` / `score` 及 dtype | 契约比对 |
| 接口规范 | `pd` ∈ [0,1] | 逐行断言 |
| 接口规范 | 禁 `ID` 入模、禁读标签路径 | AST 名称检查 |
| 接口规范 | import 白名单 | AST 检查，禁止 os.system / subprocess / socket |
| 功能正确性 | 小样本 smoke、无 NaN | 沙箱执行 |
| 功能正确性 | fit/predict 幂等、固定种子两次输出一致 | 重复运行比对 |
| 功能正确性 | 单类别、全缺失列边界输入 | 合成边界样本 |
| 指标表现 | AUC / KS / PR-AUC / F1 / 成本损失 / PSI / 分组 AUC 差异 | 时间外划分 + baseline 对照 |
| 指标表现 | test 集仅终评一次 | 运行日志审计 |
| 运行稳定性 | 单次 ≤ 60s、内存 ≤ 2GB | 子进程资源限制 |
| 运行稳定性 | 重复运行方差、依赖版本校验 | 多次运行比对 |

## 2. 报告结构（生成物模板）

```
run_id / spec / LLM 模式 / 时间 / 通过状态
├─ 检索证据：Top-K 能力节点、约束、历史失败规避项
├─ 候选方案对比：Beam Top-3 的模型族 / 采样 / 阈值 / 成本比
├─ 四层验证结论：逐项 PASS / FAIL 与说明
├─ 修复轨迹：轮次、错误签名、定向修复动作、结果
├─ 设计依据：自然语言解释（引用检索证据与历史指标）
└─ 沉淀 diff：新增/更新的图谱节点与边
```

## 4. 验收口径

- 任一必检项 FAIL 即判定本轮不通过，触发 `Diagnose → Repair`；
- 最多 3 轮修复，仍不通过则保留失败记录并回写 `FailureCase`；
- 指标门槛以 `configs/verify_credit.yaml` 为准，不得在测试集上调参或调阈值。
